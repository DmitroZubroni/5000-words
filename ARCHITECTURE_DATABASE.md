# Архитектура Базы Данных 🗄️

**5000 Words** использует **PostgreSQL** как основную реляционную базу данных. Схема спроектирована с акцентом на производительность запросов лидерборда, корректность SM-2 прогресса и минимальную избыточность данных.

## 📋 Таблицы в деталях

### `users` — Пользователи
Центральная таблица. Хранит профиль, геймификационные параметры и статус подписки.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID v7 | Primary Key. Используется UUID v7 (time-ordered) — монотонно возрастающий, что ускоряет B-tree индекс |
| `email` | VARCHAR | UNIQUE. Используется для логина |
| `username` | VARCHAR | UNIQUE. Публичное имя. Проверка уникальности case-insensitive |
| `password_hash` | VARCHAR | BCrypt хеш. Пароли никогда не хранятся в открытом виде |
| `xp` | INTEGER | Суммарный опыт. **Лига вычисляется из него на лету** (`xp / 10000`) без отдельного поля |
| `level` | INTEGER | Уровень пользователя |
| `streak_days` | INTEGER | Текущая серия дней обучения подряд |
| `last_active` | DATE | Дата последней активности. Используется `StreakService` для проверки стрика |
| `last_freeze_used` | DATE | Дата последней использованной "заморозки стрика" (Premium). Ограничение — раз в 30 дней |
| `subscription_tier` | ENUM | `FREE` или `PREMIUM`. Проверяется в `SessionService` и `FriendService` для лимитов |
| `created_at` | TIMESTAMP | Дата регистрации. Устанавливается автоматически через `@CreationTimestamp` |

**Индексы:**
- `idx_users_xp (xp DESC)` — мгновенное построение глобального лидерборда
- `idx_users_streak (streak_days DESC)` — быстрая сортировка по стрику

---

### `user_word_progress` — Прогресс по словам (SM-2)
Сердце алгоритма. Запись создаётся **лениво** — только когда пользователь впервые встречает слово.

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | UUID FK | Ссылка на пользователя |
| `word_id` | UUID FK | Ссылка на слово |
| `easiness_factor` | INTEGER | Коэффициент лёгкости SM-2 (начальный: 250 = 2.5). Влияет на длину следующего интервала |
| `interval_days` | INTEGER | Текущий интервал до следующего повторения в днях |
| `repetitions` | INTEGER | Счётчик успешных повторений подряд |
| `error_count` | INTEGER | Суммарное число ошибок. Используется для "Тренировки сложных слов" |
| `next_review` | DATE | **Ключевое поле**: дата следующего повторения. По нему `startSession` отбирает слова |
| `status` | ENUM | `LEARNING`, `MASTERED`, `FORGOTTEN` |
| `created_at` | TIMESTAMP | Когда слово было впервые встречено. Используется для подсчёта дневного лимита новых слов |

**Ограничения:**
- `UNIQUE (user_id, word_id)` — у каждого пользователя ровно одна запись прогресса на слово

**Индексы:**
- `idx_uwp_user_review (user_id, next_review)` — главный индекс. Обслуживает запрос `startSession`: "найди слова этого пользователя, которые уже нужно повторить"
- `idx_uwp_user_created (user_id, created_at)` — быстрый подсчёт новых слов за сегодня (лимит Free-плана)

---

### `words` и `translations` — Словарная база
Разделены на два уровня для поддержки многоязычности.

| Таблица | Назначение |
|---------|------------|
| `words` | Базовое слово с привязкой к языку (`language_id`) |
| `translations` | Перевод слова на другой язык с примером предложения (`example_sentence TEXT`) |

---

### `sessions` — История сессий

| Поле | Описание |
|------|----------|
| `mode` | Тип сессии: `STANDARD`, `TIME_ATTACK`, `SURVIVAL`, `WRITING`, `DIFFICULT` |
| `total_words` | Всего слов в сессии |
| `correct` / `incorrect` | Количество правильных и неправильных ответов |
| `xp_earned` | XP, начисленный за сессию |

---

### `duels` — Дуэли

Асинхронные PvP-поединки. Ключевое техническое решение — `word_ids` хранится как строка через запятую (`"14,29,43,..."`) вместо отдельной таблицы связей, что значительно упрощает запросы и гарантирует оба игрока получат идентичный набор слов.

| Поле | Описание |
|------|----------|
| `status` | `PENDING` → `IN_PROGRESS` → `FINISHED` / `DECLINED` / `CANCELLED` |
| `creator_accuracy` / `opponent_accuracy` | Точность каждого игрока в %. `null` пока игрок не завершил |
| `winner_id` | `null` при ничьей или до окончания дуэли |

---

### `friendships` — Дружба

Двунаправленная связь между пользователями через статусную машину.

| Статус | Описание |
|--------|----------|
| `PENDING` | Запрос отправлен, ожидает ответа |
| `ACCEPTED` | Дружба установлена |
| `DECLINED` | Запрос отклонён |
| `BLOCKED` | Пользователь заблокирован |

## ⚡ Производительность и проектные решения

1. **UUID v7 вместо UUID v4** — time-ordered UUID монотонно возрастает, что устраняет фрагментацию B-tree индексов при массовых вставках.

2. **Лига не хранится в БД** — вычисляется на лету из `xp`. Исключает необходимость триггеров или фоновых джобов для обновления поля при каждом начислении опыта.

3. **Ленивые записи SM-2** — `user_word_progress` создаётся только при первом контакте со словом. При 5000 слов и 10 000 пользователей это экономит до 50 миллионов пустых строк.

4. **Составные индексы** — `(user_id, next_review)` позволяет БД в одно B-tree сканирование найти все слова нужного пользователя, у которых подошла дата повторения, без полного скана таблицы.
