# Архитектура Фронтенда (React + Vite) 🎨

Фронтенд **5000 Words** спроектирован как современное Single Page Application (SPA), максимально приближенное по поведению, дизайну и анимациям к нативному мобильному приложению (iOS/Android).

---

## 🏗 Структура приложения

Архитектура фронтенда следует принципам Feature-Sliced Design (частично) и четкому разделению бизнес-логики от UI-компонентов.

```text
src/
├── core/                  # Бизнес-логика, не привязанная к визуалу
│   ├── api/               # Axios инстанс и перехватчики (interceptors)
│   ├── context/           # React Context (Auth, Theme, Toast)
│   └── routing/           # React Router (Public/Private routes)
│
├── ui/                    # Компоненты представления (Views)
│   ├── components/        # Глупые (Dumb) переиспользуемые UI элементы
│   │   ├── LanguageSelect # Кастомный селект языков
│   │   ├── StreakPopup    # Анимации огня/льда
│   │   └── TabBtn         # Кнопки навигации
│   └── pages/             # Умные (Smart) компоненты (Экраны)
│       ├── SessionPage    # Экран игры и таймеров
│       ├── DuelsPage      # Логика матчмейкинга
│       └── PremiumPage    # Экран апсейла
│
├── App.jsx                # Инициализация провайдеров и роутера
└── index.css              # Глобальные стили, Tailwind и CSS-переменные
```

## 🔄 Управление состоянием (State Management)

Мы отказались от избыточного Redux в пользу чистого React и Context API, так как приложение сильно полагается на серверное состояние (Server State).

1. **Глобальный стейт (`AuthContext`):** Хранит JWT токен, профиль пользователя (XP, уровень, подписку) и статус загрузки. Доступен в любой точке приложения через хук `useAuth()`.
2. **Локальный стейт:** Используется `useState` и `useReducer` внутри страниц для управления формами и игровым циклом.
3. **Уведомления (`ToastContext`):** Централизованная система всплывающих подсказок (`toast.success`, `toast.error`).

## 📡 Сетевой слой и API

Все HTTP-запросы проходят через настроенный экземпляр `Axios` (`api.js`):

* **Токены:** Интерцептор перед каждым запросом автоматически достает JWT токен из `localStorage` и прикрепляет его в заголовок `Authorization`.
* **Обработка 401 Unauthorized:** Если токен протух, интерцептор ответов автоматически перехватывает ошибку, очищает `localStorage` и перебрасывает пользователя на страницу `/login`.
* **Graceful Degradation:** Если пользователь упирается в системные лимиты бэкенда (400 Bad Request с ключевыми словами в `message`), UI плавно переводит его на `PremiumPage`, вместо показа сухой ошибки.

## 🎮 Игровой движок (SessionPage)

Самый сложный экран приложения. Отвечает за рендеринг карточек слов и смену игровых режимов "на лету".

* **Отсутствие ререндеров:** Использование `useRef` для хранения таймеров и счетчиков, чтобы избежать лишних перерисовок DOM дерева во время динамичных режимов (Time Attack).
* **Стейт-машина:** Логика сессии работает как конечный автомат: `Start` → `Word_1` → `Result_1` → `Word_2` → ... → `Finish_Screen`.
* **SVG Анимации:** Таймер в режиме "Time Attack" реализован через SVG элемент `<circle>` и изменение `stroke-dashoffset`. Это дает идеальные 60 FPS без лагов на слабых мобильных устройствах.

## 💅 UI/UX и Стилизация (Tailwind CSS)

Дизайн приложения ориентирован на концепцию **Dark Mode by default** (Темная тема по умолчанию) и Mobile-First подход.

1. **Отказ от нативных элементов:** Мы полностью убрали системные элементы вроде `<select>`. Вместо них используются стилизованные `BottomSheet` карточки, в которые легко попадать пальцем.
2. **Плавные микро-взаимодействия:** Все кнопки имеют состояния `active:scale-95` и `transition-all`, что создает эффект "нажатия", как в физическом мире.
3. **Скрытие скроллбаров (`.hide-scrollbar`):** Для горизонтальных каруселей (например, Ачивки) скрыт системный скроллбар, прокрутка осуществляется свайпом.
4. **Анимации Попапов:** Экран "Огонь стрика" и "Ледяная заморозка" используют `keyframes` (flame-pop, count-pop) для создания вау-эффекта.
