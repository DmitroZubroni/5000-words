# Архитектура Фронтенда 🎨

**5000 Words Frontend** — это React 18 SPA, максимально приближённое по ощущениям к нативному iOS/Android приложению. Тёмная тема по умолчанию, плавные анимации и кастомные UI-компоненты вместо стандартных браузерных элементов.

---

## 🔄 Управление состоянием

Приложение осознанно отказалось от Redux/Zustand в пользу нативного React Context API — состояние либо серверное (загружается с API), либо локальное (стейт экрана).

### `AuthContext` — главный глобальный стейт
Хранит всё, что нужно знать о текущем пользователе:
- **JWT токен** — сохраняется в `localStorage`, подхватывается при перезагрузке.
- **Профиль** — `userId`, `username`, `subscriptionTier`.
- **`loading`** — пока идёт проверка токена, роутер не рендерит ничего (предотвращает мигание неавторизованного состояния).

### `ToastContext` — уведомления
Глобальная очередь тостов. Любой компонент может вызвать `toast.success("Запрос отправлен")` или `toast.error("Что-то пошло не так")` без пробрасывания пропсов.

## 📡 Сетевой слой (Axios Interceptors)

Все запросы проходят через единый настроенный экземпляр `api`:

**Request Interceptor:**
```
Перед каждым запросом:
  token = localStorage.getItem('token')
  если токен есть → добавить заголовок Authorization: Bearer <token>
```

**Response Interceptor:**
```
При получении ошибки:
  если статус 401 (Unauthorized):
    → очистить localStorage
    → перенаправить на /login
  если статус 400 с сообщением о лимите:
    → перенаправить на /premium (без явного сообщения об ошибке)
```

## 🧭 Роутинг

Роутер разделяет пути на две категории:

| Тип | Поведение |
|-----|-----------|
| `PublicRoute` | Доступен только без токена. Авторизованных редиректит на `/` |
| `PrivateRoute` | Доступен только с токеном. Неавторизованных редиректит на `/login` |

**Важная деталь — два типа лэйаута:**
- Большинство страниц рендерятся внутри `<AppLayout>`, который содержит нижний TabBar.
- `/session` и `/duel` рендерятся **без** AppLayout — полноэкранный режим без навигации, как в настоящем мобильном приложении.

## 🎮 SessionPage — Игровой движок

Самый сложный экран. Управляет игровым циклом, сменой режимов и анимациями.

### Архитектура стейт-машины
```
LOADING → WORD_1 → [ANSWER] → WORD_2 → ... → FINISH_SEQUENCE
                                                     │
                                         ┌───────────▼──────────┐
                                         │ newLeagueName?        │
                                         │   да → LeagueScreen   │
                                         │   нет ↓               │
                                         │ streakIncreased?      │
                                         │   да → StreakPopup     │
                                         │   нет ↓               │
                                         │ ResultScreen          │
                                         └───────────────────────┘
```

### Time Attack — SVG таймер
Таймер реализован через SVG `<circle>` с `stroke-dashoffset`:
```jsx
<circle
  stroke-dasharray={`${2 * Math.PI * 34}`}
  stroke-dashoffset={`${2 * Math.PI * 34 * (1 - pct / 100)}`}
/>
```
Это чистый CSS — 60 FPS без JavaScript-анимаций, работает даже на слабых мобильных устройствах.

### Survival — сохранение жизней
**Важное техническое решение:** компонент `<SurvivalMode>` специально **не получает** ключ (`key={currentIndex}`), который бы вызывал полный ремаунт при переходе к следующему слову. Без ключа React переиспользует компонент, сохраняя стейт `lives` между словами.

## 💅 UI/UX и стилизация

### Dark Mode by default
Приложение принудительно работает в тёмной теме. В `index.html` добавлен класс `dark` на `<html>`, а `ThemeContext` блокирует любое переключение. Это осознанное дизайн-решение для снижения нагрузки на глаза при долгом обучении.

### Кастомный `LanguageSelect`
Нативный `<select>` выглядит неконсистентно на разных платформах и неудобен на мобильных. Мы заменили его на кастомный компонент — выпадающий BottomSheet с карточками языков, оптимизированный под касания.

### Анимации стрика
Два состояния одного компонента `<StreakPopup>`:

| Флаг | Фон | Иконка | Текст |
|------|-----|--------|-------|
| `frozen = false` | Огненный градиент | 🔥 | "дней подряд!" |
| `frozen = true` | Ледяной синий | 🧊 | "Premium спас твой стрик!" |

Анимации реализованы на CSS `@keyframes` (flame-pop, count-pop) с `transform: scale()` — полностью аппаратное ускорение.

### Graceful Upsell (мягкий апсейл)
Когда бэкенд возвращает `400` с сообщением о лимите, фронтенд не показывает сухую ошибку. Вместо этого:
```
catch (e) {
  const msg = e.response?.data?.message
  if (msg.includes('Дневной лимит') || msg.includes('Бесплатный план')) {
    navigate('/premium')   // ← элегантный редирект на экран покупки
  } else {
    toast.error(msg)
  }
}
```
Это превращает технические ограничения в воронку продаж.

### Скрытые скроллбары
Для горизонтальных каруселей (Ачивки в профиле) применён CSS:
```css
.hide-scrollbar::-webkit-scrollbar { display: none; }
.hide-scrollbar { -ms-overflow-style: none; scrollbar-width: none; }
```
UI выглядит чисто и нативно — скролл жестом есть, полоса прокрутки — нет.

## 📱 Мобильный UX

Всё приложение изначально проектировалось с расчётом на мобильные устройства:
- **Нижний TabBar** с крупными зонами нажатия.
- **Кнопки с `active:scale-95`** — физический эффект нажатия.
- **Отсутствие горизонтального скролла** — контент адаптируется к ширине экрана.
- **Полноэкранный режим** для сессий и дуэлей — иммерсивный игровой опыт.
